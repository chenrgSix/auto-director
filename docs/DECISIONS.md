# 设计决策记录

## ADR-028：逐镜参考与可复核的连续状态（2026-09-13，已采用）

统一角色参考默认取列表首项，会将某个人物及其构图带入反打、道具特写和空镜；仅有连续性散文无法在制作前发现矛盾。新增可选的 `visual_continuity` 契约；新 API 创作必须输出，旧包保持读取兼容，但不能自动猜测有歧义的多角色参考。参考按镜头声明顺序绑定到工作流真实输入，容量限制明确反馈。环境和风格参考生成时避免混入表演人物。

同场景以稳定实体状态键记录入/出镜状态，跨 CUT 和短暂离开画面保留；明确跳转才能重置。反打可换景别，前镜尾帧延续则要求场景/景别兼容。此检查只证明声明一致，不能证明真实模型执行。因此通过网页与 MCP 提供实际相邻边界帧和目标，记录人工或 harness 的观察，并绑定素材/目标摘要；变化后旧复核失效。

保持 C56 完整音视频拼接。记录观察不自动重拍，不在无 API 创作中隐式调用视觉模型；Codex 通过既有项目所有权与幂等服务显式局部重跑，不打开或接管 Codex 会话数据库。技术完成、规则校验与视觉复核是不同状态。

## ADR-027：模型输出完整性优先于剧本参考时长（2026-09-13，已采用）

用户明确要求只拼接、不裁剪。生成工作流的帧网格与最短档位会使成品长度偏离剧本；原按 Shot.duration 截尾会丢失收尾动作和声音。target_duration/Shot.duration 保留为创作参考和生成预算，不再限制已生成片段或成片长度。规划参数仍遵守工作流和显存上限；实际合成结果可超过参考 600 秒上限，不为凑秒数重拍、截尾或变速。

合成读取每个完整文件，保留视频和音频，格式统一时允许帧网格舍入。无声段补有限静音、声音长于画面时末帧停留；临时 PCM、最终一次 AAC 编码避免逐镜编码延迟累积。只检查有效媒体与实际片段总时长，不以剧本差额触发失败。旧成片、故事及素材保持，重新拼接成功才切换当前版本。

## ADR-026：创作包交付与用户会话 MCP（2026-09-13，已采用）

按用户要求，先建立创作包，本机 Codex 使用同一交付机制。Codex 为 MCP 客户端，AutoDirector 提供工具；后端不竞争恢复用户会话。持续会话保存创作上下文，持久化包保存可恢复成果；单会话质量优势需真实比较。制作服务与客户端生命周期分离，保留版本、确认、幂等与不确定提交保护。见 [C53](CREATION_PACKAGES.md)。

## ADR-025：相邻镜头小批次、顺序连续、原子检查点（2026-09-12，已采用）

逐镜等待重复发送 Bible、说明和工作流 schema，长片产生大量串行请求。预览准备改为每批最多 3 镜共享上下文，批内按计划顺序推导，批间传递末镜 continuity_state。保持相邻顺序，不把 CUT 直接当作无依赖边界；人物损伤、道具、时空仍可能跨切镜延续。现有字符串连续状态保持兼容，不在本轮引入实体状态重构。

批次遇到已保存提示词即结束；输入加 schema/指令超过 48,000 字符估算或预估输出超过 60,000 字符时缩小，至少按原单镜路径处理。输出估算用于选择批次，不能保证供应商 token 上限；原 100,000 字符响应限额和模型超时继续生效。失败不自动切换、递归拆批或叠加重试，避免请求放大；可在空闲时显式改为 1，再续跑缺失项。

本地严格验证后，以运行身份、输入摘要、实际工作流配置版本和取消状态为前提原子保存整批。显示已保存草稿与等待状态，全部完成前不能编辑/批准。模型生成的连续性仍需用户审核；一次速度对照与 JSON 校验不代表跨 95 镜的语义或视频质量验收。

## ADR-024：剧本在素材生成前独立审查一次（2026-09-12，已采用）

视觉 QA 已经发生在图片/视频生成之后，不能替代对剧本逻辑的提前检查。导演完成全片规划后，用现有导演模型发起独立审稿请求，检查跨镜因果、身份/道具/场景、首尾状态、转场和固定时长内的动作可行性；先审完再编写 Bible 和画面提示词。

在不改变镜数、顺序、时长和用户要求的前提下，允许逐镜文字修正并保留原稿与理由，每次最多修正 24 镜。无法局部处理的实质问题进入人工预览，显式确认后再渲染；审美偏好、合理快切/留白不作为阻断理由。审查只进行一次语义判断，格式校验仍沿用既有一次纠正预算；成功结果恢复复用，失败原稿不丢失。与生成后 QA 策略分开，关闭视觉 QA 不跳过新剧本审查。

旧计划不自动重审或改写。用户后续编辑会标注“审后已修改”；报告不承诺后续提示词、实际画面或修改后的内容已被 AI 验证。无需新增数据库表或重建生成编排。

## ADR-023：动作阶段受约束生成，审核提示词单一持久化（2026-09-12，已采用）

仅要求“先做什么、后做什么”无法表达时间分配。为新 Shot Agent 输出增加临时动作阶段，4 秒起要求 2–4 段，短镜允许省略；按剧情分配阶段而非平均切块。阶段拆解同一动作，不制造新剧情、切镜或多余停顿。所有阶段从 0 连续覆盖当前镜长，和 workflow/fps 参数分工保持。

校验后把阶段写进视频提示词并只保存这一份文本。这样审核编辑、用户覆盖、QA 与实际工作流输入共用目标，不会出现修改提示词后又被旧结构覆盖的问题。时长编辑同步缩放，OOM 分段截取局部阶段；已有数据不自动迁移，重新生成提示词时采用新要求。时间标注是模型生成指导，不能保证实际输出逐秒精确执行，也不能当作视频质量验收证据。

## ADR-022：复核驱动的修正先预览再执行（2026-09-12，已采用）

重新随机编写提示词无法利用本次画面问题，稀疏抽帧又可能将未观察到的动作误认为缺失。优化先重新观察五点视频采样与输入关键帧，再输出受字段权限限制的方案；允许模型说明证据不足或需调整工作流。用户确认后仅重做必要范围，旧版继续可播放。每次确认执行一轮修正，语义问题保留为提示，防止回到自动质检无限重画的体验；技术故障和未知提交仍受原保护。

本轮不自动改故事/时长、不修改高级覆盖、不引入视频理解服务或新编排系统。视觉模型仍读取采样图片，不能宣称逐帧视频/音频验收；工程回归与真实改善效果分开报告。

## ADR-021：先形成可复核成片，语义严格门禁显式可选（2026-09-12，已采用）

第三镜已经输出有效视频，但动作 QA 未通过后重画首尾帧，耗尽重试再次暂停。视觉模型判分的不确定性与短镜动作承载能力会让严格门禁反复中止长流水线。增加 advisory 策略，以可播放成片和明确待复核镜头作为默认网页创作体验；用户可以选择 strict 自动纠错门禁。分辨率与质量评分不降低，不把待复核写成质量合格。

advisory 每镜生成单候选，视频出来后再检查，减少中间等待和自动重画。模型检查异常记录为未完成复核；损坏视频、时长不足及执行错误仍阻塞。保持单队列和既有 PASSED 执行状态，独立 needs_review 表达质检结论，避免扩散状态机；旧 API/数据缺省 strict 防止升级静默改变既有任务，用户可为已有短片单独切换且保留故事和素材。

## ADR-020：质检独立看图，纠错编辑对应失败图（2026-09-12，已采用）

C40 已解决跨场景渲染污染和旧作业复用，但真实用户继续生成后仍有外形不合格。新检查发现 QA 请求包含约 3.45 万字符历史评语，模型引用旧结论及内部相关系数；同时纠错文字指向失败小鸡，图生图输入却仍是首帧蛋。运行时记录不应作为视觉证据，编辑指令必须与实际输入图片对应。

QA 以当前审核目标和本次图片独立评价，白名单排除历史/全局设定。图生图纠错使用对应被拒帧，保留已经正确的构图和背景；初始生成、文生图、用户参考覆盖和原提交恢复沿用已有策略。不改变门槛，也不把代码门禁或单张试跑当作全片质量已通过。

## ADR-019：审核提示权威与质检反馈分开持久化（2026-09-12，已采用）

全片 Bible 是 Shot Agent 的上下文，不是每一帧必须呈现的清单。当前镜头提示已确定人物阶段、场景和机位后，渲染层不再重复追加完整角色特征与风格场景。编辑型工作流没有独立 negative 时，限制进入实际自动 prompt；明确的高级 prompt 覆盖仍保持原文。

关键帧 QA 用结构化失败帧和有界纠错建议驱动局部重试；不根据自然语言猜测失败的是哪帧。旧输出保守沿用分数分流，现有失败素材可重新质检获得新结构。被拒的 COMPLETED 作业不能因 Continue 重用相同尝试签名，而 UNKNOWN 必须复用原提交；通过持久化重试决策和新尝试版本区分，保留旧作业、素材及用户审核文字。

## ADR-018：剧情优先的镜头数量与时长（2026-09-12，已采用）

依据原文 §14.1 / §41 与 C36 用户要求，`ceil(total / maximum)` 只表示可行镜头数下限，不是建议数量。ADR-015 的“尽量少镜头”和硬化的 2.5 秒偏好导致 30 秒计划固定为 6×5 秒；按 12 个最低必需镜头打满长片批次也会产生相同限制。

默认 Director 根据剧情动作、情绪与机位选择数量和时间，保留模型的合法非等长分配；短镜可以用于反应/细节等剧情需要，避免机械碎切，也不强制为了变化而长短交替。2.5 秒降为软建议，系统硬下限仍为 1 秒。自动批次按最多 6 个最低必需镜头的时间容量划分，每批仍最多输出 12 镜，为叙事拆镜留空间；给后续批次预留最低必要额度，确保全片不超过 240 镜。批次是输出大小限制，不指定实际镜头数。明确固定时长或容量已唯一决定数量时继续按原 12 镜批次执行，避免增加无意义模型调用。

保留精确百分之一秒归一化、模型 schema 校验、连续性上下文和取消逻辑。默认策略仅用于新计划，不重写既有剧本、提示词或素材；提示词重跑仍保留原时间线。

## ADR-017：原任务恢复与用户重跑分开（2026-09-11，已采用）

短时断网只说明读不到远端，不说明任务失败。保留 prompt_id，在配置等待期内自动重连读取；超时、重启或无法确认取消时保持 UNKNOWN 并由用户显式恢复。没有 prompt_id 时先核对历史，禁止自动重发。继续沿用 JSON 聚合与单 Worker，不引入新的队列架构。

用户重跑是新的生成尝试，必须校验版本及未结算任务，归档旧版，再失效所选范围及连续依赖。保留故事、提示词、参考图和旧产物，不用重新规划实现重跑。种子偏移可关闭且服从高级覆盖，重试版本始终改变，防止复用已完成作业而没有真正重做。

## ADR-016：先审阅分镜，再提交渲染（2026-09-11，已采用）

用户需要在投入图片/视频渲染前检查模型的镜头安排、时长和提示词。选择在现有 GenerationService 的文本准备与素材渲染之间设置持久确认点，不增加独立编排系统。网页默认启用，旧 API 与旧记录保持直接生成兼容；确认后的重试继续沿用原行为。

预览包含全部 ShotPrompts，因此还需要 Bible 和逐镜模型调用。只读取 ComfyUI 的设备/节点信息以保证预算有效，不生成图片或提交视频。当前编辑范围为标题、时长与首帧/尾帧/视频正向提示词；动作/运镜原始构思和其他 AI 参数只读，修改画面通过提示词完成。暂不支持增删/重排镜头或重新调用模型润色单镜，避免隐式改变连续性计划。

版本检查防止确认过期方案，工作流配置变动需重新预览；高级固定覆盖、素材复用和锁定规则直接展示。用户修改的提示词必须进入实际 patch，不能被 ShotPrompts 内同角色的 ai_parameters 再次覆盖。初始方案仍可一键开始，无须先执行独立保存。

## ADR-015：分镜时间契约与无顺序偏差的分配（2026-09-11，已采用）

其中默认镜头数与 2.5 秒硬约束已由 ADR-018 替代；以下保留当时决策记录。

10 秒纪录片曾被拆成 6 个 1.22～2.21 秒镜头；归一化算法在一次循环中不断扣减 remaining，却用原权重总和继续分配，导致前镜偏长。采用同一缩放系数与上下限求解，再按最大余数分配百分之一秒，避免把顺序误当成叙事权重。

仅改提示词不足以保证模型遵守节奏。每批同时生成自然语言时间要求、结构化 context 和动态 schema：每镜默认争取至少 2.5 秒，有效上限仍来自工作流/显存/用户配置；必要时降低偏好下限以兼容 1 秒总片长或窄能力区间，绝不为凑时长突破上限。建议尽量采用必要的最少镜头，但在有效最小时长内保留少量叙事机位变化。用户合法固定时长优先，已有计划保留。

本轮不新增 UI 配置项、不改显存阈值或延长 ComfyUI 视频；首先修复可复现的分配缺陷并让默认规划有可验证的节奏约束。

## ADR-014：时间线与合法渲染时长分离（2026-09-11，已采用）

实际 MiniMax H3 工作流要求 4～15 秒整数，旧流水线将 2.86 秒直接传入且误用本地 3 秒上限。采用通用动态分支元数据与时长适配，不按厂商或节点 ID 写规则。默认向上选取可覆盖目标的合法渲染长度，FFmpeg 使用原时间线时长；高级覆盖仍严格校验。模型与 workflow 最大时长共同约束渲染，无法满足时提前失败。

仅 duration 绑定节点明确声明 `api_node=true` 时豁免本地视频时长预算，关键帧仍按显存策略生成。旧分镜/图片保留并可继续生成；依赖检查或执行时刷新真实参数元数据，不增加导入网络等待，不修改已提交图和未知状态恢复逻辑。

## ADR-013：导入独立于识别与依赖检查

用户 C06 要求：取消规则识别，采用可选 AI 或手动绑定，避免导入等待；参数界面只呈现真实字段。原实现上传先 analyze，保存后强制 validate，后者拉完整 object_info。实测远端响应约 3 MB，8 秒仍未传完，构成导入等待的主要来源。

导入只本地校验/落库；AI 独立调用导演模型，总等待上限随在线 llm_timeout（C34 替代原 45 秒硬上限），可取消且只返回建议。依赖检查单独触发。删除规则推断，无 AI 失败规则回退；保留显式标签的读取以兼容已有模板。统一实际字段表，用途标签只控制已有字段的自动填充，不创造固定参数。AI 输出仍需本地验证及用户确认，不能将识别成功视作可运行。


## ADR-012：Capability、owner 与统一 limits（2026-09-10，已采用）

以用户 C03 要求为当前事实：Workflow 使用 media_type + 四类 capability；参数按角色归属自动填充，高级用户覆盖优先于自动值，但不能绕过真实素材与能力约束。总时长 600 秒保持，新计划最多 240 镜，替代 ADR-011 的按最短一秒推导 600 镜策略。旧数据不截断。完整规则见 [C03 契约](WORKFLOW_CAPABILITIES.md)。

图生图采用文生图初始参考 → 图生图关键帧的引导流程；内置模板数量不因能力分类自动扩展。高级时长先进入导演规划，当前支持统一每镜固定值；OOM 可以收紧系统参数和拆分镜头，并以实际分段尾帧覆盖原始首尾帧输入。迁移保留已提交图与 UNKNOWN 语义，不盲目重新提交。

## ADR-011：总时长与单镜头能力分离（2026-09-10，已采用）

用户要求首页提供 5/10/15/30/60/90 秒和 1～600 秒自定义，当前成片上限为 10 分钟。总时长是独立产品策略，不由本机显存或某个工作流单次生成时长决定；单镜头仍遵守工作流上限与显存预算，通过分镜完成总时长。

后端集中定义时长策略，并通过设置只读字段提供给首页。计划、镜头索引、时间线数量跟随总时长和单镜最短 1 秒推导；长计划分批请求模型，每批有明确时间段和前序镜头上下文。保持首尾帧/视频逐镜顺序渲染，不把 600 秒直接提交给单个 ComfyUI 作业。

## ADR-010：页面配置与即时生效（2026-09-10，已采用）

用户要求将配置文件改为在线配置。“连接与设置”管理 ComfyUI、LLM/VLM、密钥和运行限制，保存后无需重启。优先级为在线配置 > 既有 ComfyUI 设置 > 环境变量/.env > 默认值；数据目录和网页来源属于启动参数。

在线配置在数据目录的 `runtime-settings.json` 中原子保存，文件权限 0600。密钥写入后不通过 GET/PATCH 响应回显；空输入保留，显式清除覆盖环境密钥。切换模型端点时须同时重新提供或清除已有密钥。进行中、取消尚未退出、UNKNOWN 作业存在时拒绝变更，避免混用服务与凭据。

## ADR-001：MVP 与事实层级（2026-09-10，已采用）

原文 §2 P0 与 §57 Phase 1/2 分阶段拆分了部分共同能力。本轮将两者作为整体 MVP 目标，Phase 3 进入后续清单；VLM 为可选外部能力，启用时必须真实检查图像，未启用不能声称视觉 QA 已通过。原文不改写；实现细则在本文和模块设计迭代，任务完成必须引用验证。

## ADR-002：单进程本地持久队列（已采用）

使用 FastAPI lifespan 管理 worker，SQLAlchemy + SQLite 保存任务和实体，asyncio 单 consumer 处理队列，渲染并发 1。当前无需 Redis，禁止多个 uvicorn workers 共享该本地队列。重启可诊断中断和保留产物，不盲目重发状态不确定的外部渲染。

## ADR-003：独立 Provider 与真实/模拟边界（已采用）

生产只启用真实 ComfyUI adapter 与 OpenAI-compatible JSON/Vision Provider（不绑定 Agent Framework）。模拟服务只存在于测试/验收夹具，不作为 UI 中的默认“生成”能力。未配置依赖时提供可读配置错误。后续其他协议 Provider 可按接口加入。

## ADR-004：角色协议归一化（已采用）

原文 §10、§30、附录 C 的 capability 字段形状不同；统一为 `supports_*` + `max_duration`。动态参数按 ComfyUI object_info 校验；length/frame_count 通过明确 transform 与 fps 换算，不把 duration 秒直接写进帧数。缺少尾帧能力显式降级 I2V；没有 reference 输入时使用文本 Bible 锚点并报告能力限制。

## ADR-005：前端与权限范围（已采用）

采用 React/TypeScript/Vite 与共享 CSS 实现 UI，按需求引入组件状态管理，不为建议技术列表强制添加尚不需要的依赖。默认 loopback 单用户，不具备公网多租户权限模型。媒体与数据库本地存储；公共网络 ComfyUI 需显式开关；密钥配置方式已由 ADR-010 升级为后端保存的页面配置，环境仍可提供初始值。

## ADR-006：SQLite 聚合记录（已采用）

MVP 使用 SQLAlchemy 的 versioned JSON records：Episode 聚合包含有序 Shots、plan、bible、continuity；Workflow、Asset、RenderJob、QAResult、设置独立记录并按 parent_id 索引。SQLite WAL、事务和 version CAS 保证更新原子性。此实现没有独立 Shot 外键表；跨记录资源约束由服务层检查，后续关系查询压力出现时再迁移规范化表。数据库不在网络等待期间保持事务。

## ADR-007：先实现、后接入真实服务（用户明确要求）

不在本机部署 ComfyUI、不下载模型，先完成全部 MVP 实现与本地测试。ComfyUI 协议核对官方 docs 与 Comfy-Org 源码。用户仅在工程交付完成后提供真实 API/模型，外部门禁保持未执行。

## ADR-008：参数编辑与内置模板能力（已采用）

动态表单编辑 object_info 中的标量参数，包括模型枚举、数值、文本和布尔值。嵌套 DynamicCombo JSON 保持原样随模板传递，当前不生成递归编辑器；需要修改时重新导入 API JSON。内置模板提供协议和执行起点，不能代替真实节点/权重兼容验收。SD1.5 默认模板仅靠文本锚点，视觉参考输入由兼容替换模板承担。

## ADR-009：验收工具与质量策略（已采用）

`make check` 是统一的本地工程门禁，CI 运行同一命令。浏览器交互通过隔离夹具和实际浏览器记录，没有保留未实现的 Playwright 命令或空测试套件。VLM 未配置或 QA 关闭时，High 不进行候选视觉比较；VLM 缺失时提示跳过视觉检查；主动关闭 QA 的选择保存在单集配置中。参考资产、关键帧和视频均来自配置的真实 ComfyUI，应用代码没有模拟生成分支。

## C58：有序参考和可选辅助输入

参考图从视觉设定值生成纯视觉文本，不序列化字段名；声音/表演/负面字段不混入参考图正提示。原生 negative 绑定仍消费设定负面词，显式用户参数保持优先。bible.props 提供稳定道具身份。

Binding.optional 默认 false，仅允许 reference_image_2～9 的独立 LoadImage 连接单个真实可选 IMAGE 端口。提交前按真实资产裁去未选分支，记录保留原工作流快照和实际提交图；不以占位文件填空。编号必须连续，旧绑定仍必填。

## C58：持久等待优先于会话控制

画面确认保存于 Episode，通过网页/MCP 共同 API 推进，不持有 Codex 会话和 Worker。新建网页推荐开启，已有 API/创作包省略开关时兼容原模式。每个视频只在自己的目标帧通过确认后提交；需要前镜尾帧的连续镜按依赖逐镜进行，不能提前承诺全片关键帧一次生成。

修改完整视觉提示只作用于制作副本，历史保存旧资产；剧情和参考身份变更仍需新创作版本。图像确认是下一阶段的授权，不代替实际视频与声音验收。
