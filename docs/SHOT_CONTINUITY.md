# C57 镜头参考与连续性

目标：从项目契约、参考素材选择、制作前校验和实际画面复核四处防止跨镜头错人、错位和动作断接。适用于普通 API 创作及外部创作包；不针对某一部短片改提示词。

## 交付边界

1. `ShotPrompts.visual_continuity` 描述 `scene_id`、`visible_character_ids`、有序 `reference_roles`、`framing`、`state_in`、`state_out` 与可选 `intentional_jump`。角色使用 Bible ID，参考角色为 `character:<id>`、`environment`、`style`。状态使用稳定键和值，例如 `pen.holder: desk`；同场景后续镜头的入镜状态须接上已知出镜状态，人物暂时不入画不等于状态消失。
2. 单参考工作流取显式顺序第一项，多参考工作流按实际绑定容量装配。没有结构化信息的旧包仍可读取；旧镜头只有唯一可确定的参考时可制作，多角色歧义必须补充选择。不得以角色列表顺序决定镜头主体。容量不足必须返回提示。
3. 新 API Shot Agent 输出结构化约束；MCP 上下文导出同一 schema 和规则。制作前检查无效 ID、缺失参考、连续状态冲突；逐镜执行再次校验，明确记录实际选择。CUT/反打仍可改变构图，不一律改为前镜尾帧延续。
4. 复核提供相邻镜头的实际边界帧、参考选择及目标状态；人工/Codex 复核结果绑定实际素材，素材变化后旧结论失效。技术完成与视觉复核分别展示，MCP 可复用已有局部重跑入口。
5. 保留 C56 完整音视频拼接；不自动裁掉台词/动作，不给旧片批量改稿或重跑，不在无 API 模式偷偷调用视觉模型。

## 验收

- 双角色反打、无人道具插入、单/多参考容量、旧包歧义、跨反打状态保存、明确时间跳转、禁用镜头、预览/直接生成/外部包入口一致。
- 校验失败前不创建渲染作业；已完成素材不自动失效或重生成。选择与状态进入实际渲染和复核目标。
- HTTP 与 MCP 复核数据所有权、版本/素材过期保护、局部重跑及界面状态验证。
- 完整 `make check` 和隔离浏览器。真实模型的空间、动作与整体观感仍需后续视觉验收，不能用规则校验或模拟帧替代。
