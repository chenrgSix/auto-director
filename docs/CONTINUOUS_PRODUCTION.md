# C63 多参考连续镜头制作

## 冻结目标

将已实测的 `codex-H3-Ref2VA-连续镜头` 导演台接入项目：创作包/API → 分镜预览 → 参考素材确认 → 连续镜头组生成 → 逐段画面复核 → 完整成片。新模式不生成或要求逐镜首尾关键帧，旧首帧/首尾帧模式及历史素材保持兼容。网页与 MCP 共用制作服务。

## 契约与范围

- 新增 `REFERENCE_SEQUENCE_TO_VIDEO` 工作流能力。选择此能力即进入多参考连续模式；素材生成只需要文生图参考工作流，不要求另配关键帧工作流。
- 沿用稳定 Shot ID 和 `transition_from_previous`：CUT 等转场开始新组，CONTINUE_FRAME/CONTINUE_VIDEO 在此模式表示组内声画上下文接续。首个启用片段不能延续不存在的前段；每组最多 8 段，超限明确拒绝，不静默切断连续动作。每段仍受工作流时长与显存预算约束。
- 每段保留动作、运镜、入场/结束状态和有序人物/场景/道具参考。生成图片用的 image/start/end 提示词在新模式可省略；视频提示词与实际动作状态仍必填。已有模式提交时仍执行原关键帧校验。
- 项目将一组编译为单次 Director 请求；根据每段实际选择上传参考，编号与提示一致。`imageFile` 使用 input 下的完整相对路径，禁止借用模板素材或静默丢弃参考。模板只是结构和采样配置，不携带上次作品的素材、分段草稿或缓存选择。
- 组内开启 AV 上下文及重复前缀裁除，导演台完整导出，项目按报告中的实际导出帧数无遗漏拆回每段，然后统一拼接；不按计划秒数截尾，不把整组视频重复绑定到每段。插件的 segments 导出会释放旧段 IMAGE，因此不把该模式当作完整片段列表；报告/总帧数不匹配时阻止绑定。
- 组作业保存不可变请求、成员/素材/参数身份与 prompt_id。所有组结果就绪后原子绑定；断线/重启先核对原任务，UNKNOWN 不自动重发。取消、历史结果和原有作业保护保持。
- 第一版按整组重跑：选择一段自动扩大为该完整连续组，网页/MCP 明确返回范围。改动或禁用/重排影响组成员时不复用旧上下文。暂不提供依赖插件磁盘缓存的组内局部续采样。
- 参考图确认后直接生成视频；生成后的抽帧和连续性复核保留。模型复核与人工复核沿用显式选择，技术成功不等于动作流畅。

## 验收门禁

1. 新工作流绑定/编译、参考路径与编号、组划分与边界校验；原工作流模式回归。
2. 无关键帧提示词的创作包和 API 创作通过；参考确认前零视频提交，确认后零首尾帧生成；两段结果与完整成片一一对应。
3. 组结果数量/媒体异常不得部分绑定；缓存身份、取消、UNKNOWN、重启恢复、整组重跑、历史保留和组变更失效。
4. 官方 MCP 客户端与隔离网页验证制作模式、参考确认、组进度/复核/重跑范围。
5. 完整本地门禁。有限真实 ComfyUI 两段生成，检查实际参考数量、接续、逐段音视频与成片；完整六段、听感、跨题材画质和 CI 单独列出实际边界。
